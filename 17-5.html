两种定时器

setTimeout 只执行一次 · setInterval 每隔一段时间执行一次，直到被清除

👤 学生：胡家瑜 · 2026-11-02

① 一句话看懂两者的区别

一次性

setTimeout(fn, ms)

等 ms 毫秒后执行一次，执行完就结束。

  • 返回一个数字编号 id（第几个定时器）
  • 用 clearTimeout(id) 取消
  • 场景：延时提示、广告自动关闭、输入防抖、动画的一步
循环性

setInterval(fn, ms)

每隔 ms 毫秒执行一次，不停重复，直到被清除。

  • 同样返回一个数字编号 id
  • 用 clearInterval(id) 停止，不清理会一直跑
  • 场景：秒表、轮播图、倒计时、轮询接口
共同点：两个函数都是"把回调函数交给浏览器记账"，不会阻塞后面的代码； 时间单位都是毫秒（1 秒 = 1000 毫秒）；返回的 id 是数字，可用于取消。

实测平均值通常大于 10ms：定时器有最小间隔限制（HTML 规范要求嵌套 5 层后不少于 4ms）， 而且每次回调后还要重新排队。标签页切到后台时，浏览器会把定时器节流到 1 秒一次， 所以后台倒计时经常"变慢"。

⑥ 写法对比：什么时候用递归 setTimeout

setInterval：简单，但会"堆任务"
// 每 1 秒刷新一次数据
var id = setInterval(function () {
    hjy_loadData();          // 若这里耗时 1.5 秒
}, 1000);                    // 回调还没执行完，
                             // 下一个又到期了 → 任务堆积

// 离开页面 / 切走时必须清掉
clearInterval(id);
递归 setTimeout：上一次完成后再计时
// 用递归 setTimeout 代替 setInterval
function hjy_poll() {
    hjy_loadData();          // 先干活
    hjy_timer = setTimeout(hjy_poll, 1000);  // 干完再等 1 秒
}
hjy_poll();

// 取消同样简单
clearTimeout(hjy_timer);
三个常见坑： ① 忘记 clearInterval，离开页面后定时器还在跑（页面越用越卡）； ② 重复点击按钮创建了多个定时器，速度越来越快（正确做法：创建前先 clear 旧的，本页秒表就是这样做的）； ③ 在定时器里直接写 elapsed += 50 累加时间，回调一旦延迟，秒表就会走慢。
